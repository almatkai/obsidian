## File and platform behavior

- The process resolves vault roots to canonical paths and fences each operation against the captured directory device and file ID. File components use capability-based directory handles, no-follow opens and regular-file checks. Paths reject absolute syntax, traversal, Windows device names and alternate streams. Markdown writes exclude hidden and configuration paths. Existing hard links are refused for write operations. File creation uses exclusive creation. Append uses an append handle, independent of preview size. Confirmed edits, heading placement and bookmark updates use complete bounded reads and same-directory replacement after a metadata/identity recheck. That recheck cannot make simultaneous writes by an external editor atomic with the replacement. Delete moves a confirmed, unchanged file to the selected vault's `.trash` folder. Drafts remain open after write conflicts.
- Search caps enumeration, bytes and response pages. Inline previews are bounded. Full-content search skips files over 1 MiB and scans a bounded total per query. Note forms and full preview use a 512 KiB limit, and heading/prepend rewrites use an 8 MiB limit. The package uses Rust throughout. It directly reads only explicit vaults or paths recorded by the local Obsidian registry. Valid explicit vaults use that registry to look up their IDs. Unknown explicit paths do not trigger fallback to other vaults.
- Workspaces and search matches use Advanced URI with a registered vault ID. Without an ID, ordinary note opening uses a checked absolute path. Local daily creation/updates require the Daily Notes core plugin, and direct file writes for task/capture avoid dependence on Advanced URI. Silent writes complete without launching Obsidian. macOS uses Command shortcuts and Finder wording. Windows uses Control shortcuts and Explorer wording. [Obsidian URI](https://help.obsidian.md/uri) and [Advanced URI navigation](https://publish.obsidian.md/advanced-uri-doc/Actions/Navigation)

## Coverage limits

- Native UI retains sections, actions, metadata, forms, media grid and a Markdown detail preview. The grid uses the packaged icon and external preview instead of inline thumbnails or OS Quick Look. Exact Raycast Fuse rankings, source callout rendering, inline rich highlighting and all Moment/Luxon edge-case format tokens remain outside the fixture evidence. Startup quicklinks that depend on inbound Raycast launch context remain host dependent.
- Existing Raycast local storage is not read or imported automatically. The Actions view imports and exports confirmed JSON. Imported destructive overwrite-mode actions are rejected. Capture/Template actions use append/prepend and create missing target notes exclusively. Only explicit confirmed Note Edit replaces existing note text. Tray retention stores only vault discovery settings, without note drafts, clipboard contents or custom action templates.
- The seven upstream Raycast AI tools and the three source agent skills remain in the upstream snapshot. The Tezbar host revision has no compatible registration for those tools or inbound resources, so the manifest advertises the ordinary commands only.
- Locked dependencies, original resources and per-target file hashes are inventoried in development packages. The verified source retains an empty portable artifact and file inventory, and the packager inserts its per-target file inventory into the ZIP copy. Protocol and artifact fixtures own their files and mock all host effects. Live Obsidian routing, macOS/Windows integration and actual GPUI acceptance are separate from runtime fixture evidence.

An append form with a configured template exposes a secondary, explicit expansion action. Dedicated template routes retain expansion. | SEC-02, headings on new targets | **Verified condition, upstream parity pending.** A new daily note can use a heading in its template seed. The pinned Raycast extension delegates all three heading cases to Advanced URI, and its reference describes insertion below a named heading. The snapshot establishes no rule for creating a missing heading. The proposed automatic heading synthesis was rejected. See `src/ops.rs:216`, `src/markdown.rs:525`, `src/markdown.rs:615` and `upstream/src/obsidian/internal/obsidian.ts:158`. |

Windows volume-specific behavior remains untested. See `src/view.rs:310`, `src/view.rs:785`, `src/main.rs:1027`, host `crates/tezbar-ui-model/src/extensions/runtime.rs:319` and `runtime.rs:698`, and host `apps/tezbar/src/surfaces/extension_runtime/view.rs:1784`. |
